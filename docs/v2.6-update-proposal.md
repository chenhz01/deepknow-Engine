## 一、为什么做（动机）

v2.5 档案是访谈生成的静态资产——人变了，档案不知道。对话流里其实天天产生增量（新项目、新雷点、生活变化），但直接自动写入有两大坑：

1. **隐私坑**：对话里混入的敏感信息（手机号、住址、他人隐私）会绕过同意关卡直接漂进档案。
2. **失真坑**：AI 自动改档案=档案漂移，"懂"的信任基础塌掉；断章取义的记忆比没有记忆更伤。

先例背书：tigerless/agent-memory 的 Manage 层已验证此模式——无人值守只能 add/update，**删除与敏感变更必须提案确认**。

## 二、五步管线（设计）

```
对话流 ──→ ①提取（值得记的判断）──→ ②提案（proposal.json，不动档案）
              │                              │
              ▼                              ▼
        （提取零写入）          ③人工确认（用户看提案、批/驳/改）
                                             │ 批准
                                             ▼
                             ④入库（过 validate.py 隐私扫描 + Schema 校验）
                                             │
                                             ▼
                             ⑤再生（重新派生 card 层 + sha256 更新）
```

分工纪律（延续 v2.5 原则：引擎算条件，LLM 只管说话）：
- **LLM 负责**：①提取与②提案的"内容判断"（这段话值不值得记、属于哪个章节、建议改成什么）。
- **确定性代码负责**：③④⑤的闸门——提案格式校验、隐私扫描、diff 生成、入库与派生。LLM 永远没有直接写档案的路径。

## 三、权限矩阵（v1 草案，待脑暴修订）

| 变更类型 | 路径 | 理由 |
|---|---|---|
| 新增事实（新项目、新习惯） | 提案 → 确认后入库 | 事实性内容，错了污染档案 |
| 修改既有章节内容 | 提案 → 确认后入库（带 diff 对比） | 用户必须看到"从什么改成什么" |
| **删除任何内容** | 提案 → 确认，且留 supersede 链不物理删 | 删除最高危，永不静默 |
| 基因层任何字段 | **不在提案范围内**（v2.6 硬边界） | 基因层慢变量只能走人工复访访谈 |
| 未完线状态机流转 | 引擎自动（open→cooling 等） | 已有确定性规则，不属于档案内容变更 |
| 涉及第三方/他人的信息 | 提案强制降级到 family 以下 + 高亮提示 | 他人隐私不是本人能单方面授权的 |

## 四、提案文件形态（草案）

```jsonc
{
  "proposal_id": "p-20261104-001",
  "source": "session 摘录（脱敏引用，存 hash 不存原文）",
  "target": { "layer": "dossier", "section": "3.项目主线", "field": "active" },
  "action": "add | update | supersede",
  "before": null, "after": "……",
  "confidence": 0.0,          // LLM 自报，仅排序用，不作为免确认依据
  "status": "pending | approved | rejected | expired"
}
```

- 提案默认 **7 天过期**（expired）——不确认=不动，防止提案堆积绑架用户。
- 批量确认上限：单次 ≤5 条（对齐分批纪律）。
- 所有提案合并展示一个 `proposal review` 界面/命令，不用对话里"要不要我记住？"打断人。

## 五、与现有三件的接缝

- `validate.py`：入库前复跑隐私扫描+Schema 校验（**第四道闸**：提取→提案→确认→扫描，少一道不过）。
- `card-gen.py`：入库后重新派生 card 层，sha256 更新——权限模型不因更新回路松动。
- `hooks_engine.py`：只读档案层，无写入路径；引头用到的"未完线"更新仍走自己的状态机。

## 九、对攻脑暴后的最终版设计（24 场修订，以此为准）

### 9.1 架构澄清（重大）
- **提取器 = skill，不是后台进程**。本仓没有对话日志，"对话→提取"由宿主 Agent（Claude Code/DSH）在对话边界调用 skill 完成，对话原文作参数传入。仓库交付的是契约：提取 prompt 模板（核心锁死+版本号）+ proposal schema（开放共建，只增不改+CI）。

### 9.2 闸门链（三道变五道）
```
对话 → ①提取（宿主skill，subject绑定+verbatim引文，指令类零写入）
     → ②提案（零写入，jsonl按周分片）
     → ③确认（白话二键卡片为主/CLI为开发者通道；strip ANSI；摘要先行；连批≥3二次确认）
     → ④扫描（validate隐私扫描+行为动词检测+主语亲属词硬规则，任一命中exit 2）
     → ⑤入库（timeline追加式写入→重派生card→输入清单哈希同存）
```

### 9.3 权限矩阵（修订版）
| 变更类型 | 路径 |
|---|---|
| 新增/修改 | 提案→确认→扫描→入库（timeline append，含 observed_at/source_id） |
| 删除 | 确认+supersede 链（v2.7 实现链结构，v2.6 先做不物理删） |
| 基因层 | 不进提案回路（硬边界不变） |
| 第三方信息 | **默认不提取**，只留匿名角色描述；确需留存强制标注"涉第三方、未告知" |
| 主体分离 | 提案分 `subject`（数据主体）/`confirmer`（确认人）；本人建档同意+随时否决优先于子女确认 |
| 老人否决 | 老人说"别记这个"=即时否决+标 supersede；档案有口语播报版；情感章节标注"子女填写待本人确认"，老人改一字即覆盖 |
| 雷点章节 | 分话题雷点（AI 沉默）/关系雷点（不代避，提示子女人谈）；半年未触发提议"要不要聊一次" |

### 9.4 生命周期（惰性版，防沉默失败）
- **随读判定**，禁后台定时器：CLI 读取时比对 created_at（UTC+显式时区），超期拒绝并打印原因；入库器二次校验；`validate --lifecycle` 自检命令输出全部过期未清理提案。
- 过期不销毁：**冻结转摘要**（"两周回顾 N 件事等你勾选"）；时效分级——用药类 24h、生活类 14 天。
- **季度核对仪式**：未完成核对→档案降级只读旧档，AI 引用附"已 90 天未与本人核对"标签。

### 9.5 排序与矛盾
- confidence 撤排序位，换引擎可验信号：引文精确匹配/现有条目冲突检测/层风险置顶。
- 矛盾处理：时间不重叠的状态演进自动 append 标 `contradicts`；同 observed 窗口内同属性正反提案才升级人工。

### 9.6 多设备（诚实方案）
明说不支持实时同步。export 打包未同步分片+设备 id；import 按 UUID 去重合并永不覆盖；互为 supersede 双保留标 conflict。

### 9.7 冷启动与叙事
- 发布叙事"先访谈后生长"：内置 10 问导入访谈生成种子卡片；预置演示对话+生长前后档案。
- README 主张："你的档案你签字"——确认制是信任资产不是阉割。
- 驳回数据：本地聚合结构特征（不存原文），opt-in 匿名导出。
