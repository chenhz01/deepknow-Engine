# v3.0 立项草稿：身份前提层（Identity Premise）

> 状态：🟡 草稿（善伦 2026-11-04 指令立项：身份前提升级，示例身份"资深20年架构师"）。
> 未经对攻脑暴修订前，本文是讨论底稿不是实现依据。
> 一句话：档案不但记录"他是谁"，还规定 **AI 用什么身份姿态跟他说话**——对其专业领域按同侪对话，不科普、不越位、不谄媚。

## 一、动机（费曼层）

现在的档案回答的是"他知道什么、他讨厌什么、他想怎么被爱"，但没回答一个每天都被问到的问题：**该把他当新手还是专家？**

同一个"我打算重构整个服务"，对小白要说"什么是重构、风险在哪"，对资深架构师要说"你的边界怎么划、回滚方案呢"。说低了（科普他懂的东西）=轻慢；说高了（假设他懂他不懂的）=失真。v3.0 把这件事从"LLM 自己猜"变成"档案规定"。

## 二、身份前提是什么（机制层）

**定义**：身份前提=档案对象的社会/职业身份及其对话姿态契约。它是**慢变量**——职业身份几年才变一次，按 v2.6 硬边界归入**基因层**，不进提案回路，只能走人工复访访谈更新。

```jsonc
// gene.json 新增字段（草案）
"identity": {
  "role": "资深架构师",
  "years": 20,
  "domains": ["分布式系统", "高并发", "团队技术管理"],
  "authority": ["技术选型", "架构边界", "代码评审"],   // 让渡判断权的领域
  "outside_authority": ["投资决策", "健康"],            // 明确不让渡的领域
  "vocabulary_level": "expert",       // expert | practitioner | layman
  "peer_rules": {
    "no_explaining_basics": true,     // 不科普其领域基础知识
    "use_jargon_freely": true,        // 直接用行话
    "challenge_as_peer": true         // 同侪位质疑：事实错误照纠，不因身份让步
  }
}
```

## 三、三条说话规则（LLM 契约，prompts 层）

1. **同侪位**：在其 `authority` 领域内，AI 以同侪/助手姿态提观点，让渡判断权（"你怎么划边界"而非"你应该这样划"）。
2. **行话位**：`vocabulary_level=expert` 时直接用领域行话，禁入门级解释。
3. **不越位**：
   - AI **不得自称拥有该身份**（speak_as=self 硬边界延续 v2.5：禁"我是20年架构师"）——身份前提是**对他**的姿态，不是 AI 的人设。
   - `outside_authority` 领域照常行使档案职责（钱袋生死线拦截不因身份豁免）。
4. **反谄媚护栏（对齐 F11）**：让渡判断权≠同意。同侪位质疑照样执行 RA-1 前提审计——身份高的人说错话，纠错的义务更重不是更轻。

## 四、分工纪律（延续"引擎算条件，LLM 只管说话"）

- **确定性代码**：`card-gen.py` 新增派生 `identity.md`（装载时生成，进 card 层权限体系，sha256 在链）；schema 校验身份字段合法性（years 为整数、domains 非空数组）。
- **LLM**：读 identity 卡，按三条规则说话。规则违不违，靠提取契约+对抗测试盯，不靠引擎读心。

## 六、开放问题（进对攻议题 A）

1. 身份前提和"被爱方式"冲突时谁赢？（他是架构师=爱讲理 vs 他被爱方式=别讲道理只要陪着）
2. 多重身份（架构师+父亲+病人）当次对话取哪个镜头，谁决定？
3. 身份变了（退休/转行）走复访访谈——但访谈谁来触发？无后台定时器的惰性判定下，怎么防止身份漂移 90 天没人管？

## 七、对攻修订（12 场后定案，详见 v3v4-brainstorm-log.md）

1. **推翻 challenge_as_peer** → **信息增量发言**：只在握有对方不知道的案例/边界数据时开口，否则沉默；挑战质量用"是否改变过决策"度量。
2. **推翻镜头模型** → 身份由本人信号触发、允许混镜、默认跟人不跟角色。
3. identity **强制含关系身份维度**（一家之主/过来人/被需要的人）；对老人转**求助式姿态**。
4. 新增**第四条说话规则·镜像降级**：代用户对外发言时禁行话位。
5. **背书动词黑名单**（担保/以X年经验→exit 2）+ **第一人称×身份词 denylist 输出过滤器**——"不得自称"从 prompt 祈祷升级为结构拦截。
6. **gene 层 sha256 基线锁**；authority 变更须复访访谈+双人核对（部分采纳白名单固化）。
7. identity.md **对外派生剥离**：authority 不出卡、years 模糊"资深"、domains 到行业级。
8. **上下文裁剪三层级**：权限规则引擎侧→身份压缩稿≤80token 永驻→常驻卡 LRU 裁剪；身份永不裁。
9. 让渡话术**对议题不对人**；身份含职业+关系双维度。
