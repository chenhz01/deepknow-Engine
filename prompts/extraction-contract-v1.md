# 提取契约 v1.0（extraction-contract-v1）——宿主 Agent 调用规范

> 状态：✅ v2.6 T1-min 交付（契约文本，宿主 LLM 执行时逐条遵守）。
> 定位：本仓库没有对话日志，"对话→提取"由**宿主 Agent**（Claude Code / DSH / 任意 Agent）在对话边界调用本契约完成。本契约是 LLM 唯一被授权的提取入口；任何绕过它直接产出档案写入的行为都是越权，闸②会拒。

## 0. 零写入铁律（最高优先级）

你的输出**只能是 proposal JSON Lines**（每行一个提案对象，符合 `schema/proposal.schema.json`）。
- ❌ 禁止直接改 `dossier.json` / `gene.json` / 任何 derived 文件
- ❌ 禁止产出"待执行动作""提醒我去做""以后每天…"类指令——闸②行为动词检测命中即拒
- ❌ 禁止在 after 里复述整段对话——只写一句可独立成立的事实
- ✅ 你唯一被允许的"写"，是把你提议的变更**写成提案**，等人确认

## 1. 提取判据：什么值得记

只提取满足以下全部条件的增量信息：
1. **关于数据主体本人的事实变化**（新项目/项目状态变化、新雷点、被爱方式变化、新习惯、用药就医、生活安排变化）；
2. **有对话原话支撑**——你要引用 verbatim 原文片段作 `quote`（≤300字），`after` 必须能从 `quote` 直接推出，不允许脑补；
3. **档案里还没有，或与现有条目矛盾**（矛盾照提，注明 action=update，人自己裁决）；
4. **频率参考**：一段对话通常 0-3 条，宁缺毋滥。情绪倾诉没有事实增量时不提。

明确不记：笼统感受（"他今天心情不好"无具体事实不记）、你自己的建议、未发生的计划（除非主体明确宣布决定）。

## 2. 主体绑定（防主语错位）

- `subject` 永远填**档案主体**（`subject.relation` 按档案 meta），对话里提到的其他人**不是**提取对象。
- 对话中出现"我妈/我爸/我儿子/我闺女/我们领导…"等亲属或第三方主语时：
  - 该信息**默认不提取**；
  - 确属必要（如影响照顾主体的安排）→ `third_party.anonymous_role` 填匿名角色（"他的母亲""合作方A"），且 `after` 里**必须用匿名角色指代，禁止出现亲属词**——闸④亲属词主语规则命中即拒。
- 主语拿不准就不提。错主语的事实一旦入库即污染档案，宁可漏、不可错。

## 3. 敏感内容纪律

- 对话中出现的手机号/身份证/邮箱/精确住址 → 不进任何字段（闸④隐私扫描兜底，但契约层先自律）。
- `source_id` 只填会话标识（如 `sess-20261104-a1`），不存对话原文。
- 第三方信息：`disclosed: false` 是默认值，档案侧会高亮"涉第三方、未告知"。

## 4. 时效分级（class 必填）

| class | 适用 | 过期 |
|---|---|---|
| `medication` | 用药、就医、复查、剂量变化 | 24 小时（过期冻结转摘要） |
| `life` | 其余生活类 | 14 天 |

## 5. 输出格式（唯一合法输出）

每行一个 JSON 对象（JSON Lines，UTF-8）：

```json
{"proposal_id":"p-20261104-001","schema":"proposal/1.0","created_at":"2026-11-04T10:30:00+08:00","class":"life","subject":{"id":"chen","alias":"陈先生","relation":"self"},"confirmer":{"id":"son","alias":"小陈","relation":"son"},"source_id":"sess-20261104-a1","quote":"「体检报告出来了吗？……血压那项高了不少，医生让我把降压药换成进口的。」","target":{"layer":"dossier","section":"actions","field":null},"action":"add","before":null,"after":"主体主诉：医生建议将降压药更换为进口品牌（待确认具体药名与时间）","confidence":0.7,"status":"pending","third_party":null}
```

没有值得记的 → 输出空（零行）。**空输出是合法且被鼓励的输出。**

## 6. 调用方（宿主 Agent）接线方式

```
1. 对话自然收尾时（或用户显式说"记一下"），以最近对话原文为参数，按本契约提取；
2. 把产出的 JSONL 写入临时文件；
3. 调用: python scripts/proposal.py submit <临时.jsonl> --dir <提案目录>
   （闸②在这里跑：契约校验+行为动词+亲属词+隐私归一扫描，任一命中整包拒绝 exit 2）
4. 提醒用户择时跑 review 确认——不要在对话里追问"要不要我记住？"打断人。
```

## 7. 本契约的开放与锁死边界（对社区）

- **锁死**（改了闸会拒）：零写入铁律、quote 必填且≠after、subject/confirmer 分离、匿名角色纪律、schema 版本字段。
- **开放共建**：提取判据的措辞、频率建议、行业化判据（如照护/教师/客户档案的场景附加条）——欢迎 PR 增补，不得削弱安全条款。
